### 更新
1.新增 FunctionParserTool，该工具深度集成了业界标准的 libclang 库。它能够像编译器一样精确解析C/C++源码的抽象语法树（AST），从而：
提取出所有的函数定义及其所在行号。
识别出文件内所有的函数调用。
为未来实现跨文件依赖分析和调用链可视化奠定了坚实的数据基础。

2.提供 Dockerfile 和 docker-compose.yml，将整个应用及其所有系统依赖（包括特定版本的clang和libclang）完整封装到一个独立的、可移植的Docker容器中。

##### 1. `BuildSystemAnalyzer`
*   **职责描述**: 此模块负责在分析开始前扫描 `Makefile` 或 `CMakeLists.txt` 等构建脚本。它通过正则表达式提取全局定义的编译宏（如 `-D MACRO_NAME`）和目标架构标志（如 `-march=armv8-a`）。
*   **对架构的作用**: 它为后续的分析流程提供了关键的**“先验知识”**或称“构建上下文”。原架构在分析单个文件时是“盲目”的，而此模块提供的上下文能让分析引擎（`EnhancedOrchestratorAgent`）更准确地理解条件编译块（`#ifdef`）的真实意图。

##### 2. `CrossFileCorrelator`
*   **职责描述**: 作为分析结果的“聚合器”，此模块接收所有单文件的分析报告。它在内存中构建一个全局符号表，用以记录每个函数在不同架构下的实现情况、定义位置以及调用关系。
*   **对架构的作用**: 将原架构产出的零散的“点状”信息连接成一张“网”。它的核心价值在于发现了原架构无法企及的项目级风险，如最典型的**“多架构实现缺失”**——即一个函数在一个架构版本中被调用，但在该版本下却没有对应的实现，这通常会导致链接期错误。

##### 3. `DependencyGraphGenerator`
*   **职责描述**: 该模块将 `CrossFileCorrelator` 产出的抽象依赖关系和风险点，转换为符合 ECharts 等前端图表库规范的JSON数据结构（即 `nodes` 和 `links`）。
*   **对架构的作用**: 它是整个分析流程的**最终呈现层**。它将枯燥的结构化数据转化为直观、可交互的依赖关系图谱，极大地降低了用户理解项目架构复杂度和潜在风险的认知门槛。

---
### 核心改动点

为集成上述模块，对原有的演示脚本 (`demo2.py`) 执行了以下重构：

*   **执行流重构**: `main` 函数的执行流程被改造为更清晰的多阶段流水线：
    1.  **阶段一**: 运行 `BuildSystemAnalyzer` 获取项目构建上下文。
    2.  **阶段二**: 运行 `EnhancedOrchestratorAgent` 对每个文件进行深度分析。
    3.  **阶段三**: 运行 `CrossFileCorrelator` 和 `DependencyGraphGenerator` 进行项目级关联与可视化数据生成。
*   **统一报告输出**: 替换了原有的简单JSON保存逻辑。现在系统会生成一个唯一的、结构化的项目报告文件，该文件**同时包含**构建上下文、单文件分析详情、项目级风险列表和前端可视化图谱数据。

---
### 优化目标与预期

*   **提升分析深度**: 系统不再仅仅回答“文件A里有什么”，而是能够回答“项目X的函数 `foo` 在其RISC-V分支中缺少实现，将导致链接错误”。
*   **提升结果可读性**: 通过可视化依赖图谱，让复杂的项目架构和潜在风险一目了然。
*   **构建完整工作流**: 实现从项目源码输入到多维度分析、再到可视化报告输出的端到端闭环。
